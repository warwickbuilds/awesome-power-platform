# Contribution Guidelines

Please note that this project is released with a
[Contributor Code of Conduct](code-of-conduct.md). By participating in this
project you agree to abide by its terms.

---

## Adding to this list

Please ensure your pull request adheres to the following guidelines:

### Quality Criteria

- **Link to the resource**: Make sure it's publicly accessible and working
- **High quality**: Only suggest resources that are well-maintained, documented, and provide real value to Power Platform users
- **Relevant**: Resources must be directly related to Microsoft Power Platform (Power Apps, Power Automate, Power BI, Power Pages, Power Virtual Agents, or Dataverse)
- **Not a duplicate**: Check that the resource isn't already listed
- **Recent and maintained**: Avoid outdated or abandoned resources

### Formatting

- Use the following format: `[resource-name](link) - Short description.`
- Descriptions should be clear, concise, and explain the value of the resource
- Keep descriptions under 25 words when possible
- Use title case for resource names
- End descriptions with a period
- Check your spelling and grammar

### Categories

Add your resource to the most appropriate section. If you're unsure about the category or think a new category is needed, please mention it in your pull request.

### Examples

Good:
```
- [Power Platform CLI](https://docs.microsoft.com/powerapps/developer/data-platform/powerapps-cli) - Command line interface for Power Platform development and deployment.
```

Not so good:
```
- [some tool](http://example.com)
- [Power Platform CLI](http://example.com) - A tool for doing stuff with Power Platform that is really awesome and everyone should use it because it makes everything easier
```

### Link Validation

- Ensure all links work and point to the intended resource
- Use HTTPS when available
- Link directly to the resource, not to a redirect or landing page
- For GitHub repositories, link to the main repository page unless linking to specific documentation

## How to Contribute

### Step-by-step process

1. **Fork this repository** to your GitHub account
2. **Access the readme.md file** in your fork
3. **Click the edit icon** to start editing
4. **Add your resource** in the appropriate section following the formatting guidelines above
5. **Commit your changes** with a descriptive commit message like "Add [Resource Name]"
6. **Create a pull request** from your fork to this repository
7. **Wait for review** - we'll review your submission and may ask for changes

### Pull Request Guidelines

- **One resource per pull request** - this makes it easier to review and discuss individual additions
- **Descriptive title**: Use format like "Add [Resource Name]" or "Add [Category] section"
- **Include reasoning**: In the PR description, briefly explain why this resource should be included
- **Be patient**: Reviews may take some time, and we may request changes

### What happens next?

After you submit your pull request:
- We'll review the resource for quality and relevance
- We may ask questions or request changes
- Once approved, your contribution will be merged and become part of the list
- You'll be credited as a contributor to the project

Thank you for helping make this a valuable resource for the Power Platform community!


## Updating your PR

A lot of times, making a PR adhere to the standards above can be difficult.
If the maintainers notice anything that we'd like changed, we'll ask you to
edit your PR before we merge it. There's no need to open a new PR, just edit
the existing one. If you're not sure how to do that,
[here is a guide](https://github.com/RichardLitt/knowledge/blob/master/github/amending-a-commit-guide.md)
on the different ways you can update your PR so that we can merge it.
